# Customer Portal Lite

## What this adds

Pest Mantra now includes a secure, mobile-first customer portal without introducing a separate customer/account database.

Customers sign in with:
- the same 10-digit mobile number stored on their service records, and
- a revocable 12-character access code generated by an authenticated Super Admin or Office Admin from an existing Project detail page.

The full access code is only returned when it is generated/regenerated. The backend stores a bcrypt hash, not the readable code.

## Customer experience

Public routes:
- `/customer/login` — customer portal sign in
- `/customer/portal` — authenticated customer dashboard

The dashboard shows only records matching the access record's company, branch, and customer phone:
- Jobs and current technician/schedule status
- Sent/accepted/rejected quotations (draft quotations are intentionally hidden)
- Customer accept/reject action for valid SENT quotations
- Issued/payment-stage invoices and outstanding balance (draft invoices are intentionally hidden)
- AMC/service contracts and upcoming visits
- Finalized service reports
- Links to existing verified service-report and feedback pages

No payment gateway, complaint workflow, or customer profile editing is introduced in this Lite version. Those would require additional business/provider decisions and are intentionally outside this feature pass.

## Admin access management

On an Admin Project detail page, the new Customer Portal card can:
- enable customer portal access
- generate/regenerate a code
- copy the login URL + mobile + code for manual sharing
- revoke portal access
- show expiry, last-used date, and code hint

A project must be linked to a company and branch before portal access can be enabled.

## Security model

- Customer access is company + branch + phone scoped.
- Access codes are bcrypt-hashed.
- Access codes expire after one year and can be regenerated/revoked.
- Login is protected by the existing login rate limiter.
- Portal sessions use a separate JWT token type (`customer_portal`) with a 12-hour expiry.
- A session version is checked against MongoDB on every portal request. Regenerating or revoking access invalidates existing portal sessions.
- Draft quotations and draft invoices are never exposed to customers.
- Service reports are limited to finalized records.
- Invoice payment references, internal quotation notes, signatures, photos, and admin-only fields are not returned by the portal dashboard API.
- Customer quotation decisions are server-enforced: only a non-expired SENT quotation belonging to the exact portal tenant/phone may be accepted or rejected.

## Backend API

Under `/api/v1/customer-portal`:

Public/session endpoints:
- `POST /login`
- `GET /me`
- `PATCH /quotations/:quotationId/decision`

Admin endpoints:
- `GET /access/project/:projectId`
- `POST /access/project/:projectId`
- `DELETE /access/project/:projectId`
